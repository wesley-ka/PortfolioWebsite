# Aider Architectural Conventions & Coding Instructions

This repository is an **Interactive Cryptographic Sandbox & Security Portfolio** built with Svelte 5, Tailwind CSS v4, Vite 8, and Cloudflare Pages Functions.

When making modifications, diagnosing errors, or implementing features, strictly adhere to the following guidelines:

---

## ⚡ 1. Svelte 5 Runes & Reactivity
This project uses **Svelte 5** (`svelte` >= `^5.0.0`). Do NOT write Svelte 4 legacy code.
* **State Declaration**: Use `$state()` for reactive variables. Avoid plain local variables for reactive state.
  * **Correct**: `let value = $state(false);`
  * **Incorrect**: `let value = false;` (if it needs to be reactive)
* **Reactive Derivations**: Use `$derived()` instead of legacy `$:` reactive declarations.
  * **Correct**: `let double = $derived(count * 2);`
  * **Incorrect**: `$: double = count * 2;`
* **Side Effects**: Use `$effect()` for running code when dependencies change.
  * **Correct**: `$effect(() => { console.log(value); });`
  * **Incorrect**: `$: console.log(value);`
* **Component Mounting**: Svelte 5 mounts applications using the `mount` function. Do not use legacy class instantiation (`new App(...)`).
  * **Correct**: `mount(App, { target: document.getElementById('app') })`

---

## 🎨 2. Tailwind CSS v4 Styling
This codebase uses **Tailwind CSS v4** (`@tailwindcss/vite` and `tailwindcss` >= `4.0.0`).
* **No `tailwind.config.js`**: Do not create or edit `tailwind.config.js`. Tailwind v4 configures options directly in CSS.
* **Theme Configuration**: Theme customisations (fonts, animations, custom shadows, colors) are located in [src/app.css](file:///Users/w/WebProjects/PortfolioWebsite/frontend/src/app.css) under the `@theme` directive.
  ```css
  @theme {
    --font-sans: 'Inter', 'Outfit', sans-serif;
    --shadow-glass: 0 8px 32px 0 rgba(0, 0, 0, 0.4);
  }
  ```
* **CSS Variable Injection**: Use CSS variables or Tailwind utility classes defined in `@theme`.
* **Glassmorphism Aesthetic**: The application uses high-end glassmorphic components. Utilize background blurs, thin semi-transparent borders (`border-white/5`), and radial gradients (`bg-slate-950/40 backdrop-blur-md`).

## 🔄 3. Dual-Mode Execution (Local vs. API API-Proxy)
The application communicates with a containerized Spring Boot Cryptographic Backend. To support offline deployment, it implements a **dual-mode architecture**:
* All API actions in `src/services/` (e.g., [src/services/api.js](file:///Users/w/WebProjects/PortfolioWebsite/frontend/src/services/api.js)) must wrap endpoints using the `apiCall(path, body, mockFallbackFn, method)` utility.
* **Connection Testing**: `checkBackendConnection()` probes the backend health and caches the result for 30s (`isBackendOnline`).
* **Fallback Implementation**: Always provide a high-fidelity client-side javascript fallback function (`mockFallbackFn`) using the Web Crypto API or local math libraries if the backend is unreachable.
* **Telemetry**: Push actions, latencies, and responses into the `apiLogs` Svelte store so the dashboard can render operations in real-time.

---

## ☁️ 4. Cloudflare Pages Functions (Serverless Backend)
The backend routing and proxies are serverless functions located in the `functions/` directory.
* **Routing Scope**: File paths under `functions/` determine matched URL endpoints:
  * `functions/api/[[path]].js` only intercepts requests starting with `/api/` (i.e. `/api/*`). It CANNOT intercept frontend routes like `/connect`, `/hi`, `/hello`, `/voting`, or `/index.html`.
  * To intercept, redirect, or block (e.g., return a `503 Service Unavailable` response for) a root-level frontend route like `/connect`, you must create a dedicated function file at `functions/connect.js` (or `functions/connect/[[path]].js`).
* **Client-Side vs. Edge Routing**: Direct browser navigation to routes without a dedicated edge function (e.g., `/connect`) falls back to `index.html` and is handled inside `src/App.svelte` using Svelte's router (by checking `window.location.pathname`). To temporarily disable or block a page entirely, use an edge block under `functions/` rather than only adding checks in `functions/api/*`.
* **Request Handler**: Export async functions named after HTTP methods or use `onRequest` (e.g., `export async function onRequest(context) { ... }`).
* **Environment Variables**: Access configuration values (like `API_ORIGIN`, `API_KEY`, `TELEGRAM_BOT_TOKEN`) from `context.env` rather than `process.env`.
* **Responses**: Return standard Web API `Response` or `Response.json(...)` objects.

## 🔑 5. Cryptography & Security Conventions
* **No Secrets in Frontend**: Never commit or hardcode credentials, private keys, or API tokens in files compiled to the frontend bundle. Utilize serverless functions (`functions/`) to proxy requests and inject keys securely.
* **Web Crypto API**: Prefer the browser's native `crypto.subtle` for standard operations (AES-GCM, SHA-256 digests).
* **BigInt Curve Operations**: For custom curve calculations (Schnorr proofs, ECDSA fallback, BigInt math), import functions from [src/services/crypto-math.js](file:///Users/w/WebProjects/PortfolioWebsite/frontend/src/services/crypto-math.js).
* **Post-Quantum Cryptography (PQC)**: Kyber/ML-KEM-768 is implemented via `@noble/post-quantum/ml-kem.js`. Maintain IND-CCA2 security conventions (e.g. handling implicit rejection correctly; never expose raw shared secrets).

* **Build Verification**: Run `npm run build` to verify there are no Svelte compiler errors, Vite loader errors, or syntax errors.
* **Dev Server**: For local validation of pages functions + frontend assets, use `wrangler pages dev dist` (run via `npm run pages:dev`).
